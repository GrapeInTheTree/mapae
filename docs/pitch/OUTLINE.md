# 피치덱 구상 — 본편 16장 + 부록 4장

> 산출물 ① 피치덱의 설계도. 기존 `mapae_pitch_v2.pptx`(15장)의 **뼈대와 강한 카피는 승계**하고,
> 낡은 증거(테스트 108·tx 19·MCP 부재·공개 URL 부재)를 전부 현재로 갱신하며, 새로 생긴 세 덩어리
> (제품 웹 · MCP · x402 정산)를 본편에 편입한다. 각 장에 [승계]/[갱신]/[신규] 표기.

## 장수에 대한 답

**본편 16장 + 부록 4장.** 20장짜리 본편은 과하다 — 심사자는 수십 개 지원서를 훑고, 훑는 속도에서
살아남는 건 "한 장 = 한 주장"이다. 12장이면 제품·MCP·x402 중 하나를 버려야 하고, 그건 이번 주에
만든 것을 숨기는 일이다. 부록은 산출물 ③(컨트랙트 링크)·④(기술 상세)와 재료를 공유하므로 덱을
무겁게 하지 않으면서 "더 파고들 사람"의 질문에 미리 답한다. 데모데이 발표용은 이 본편에서
6~8장을 추려 쓰면 된다 — 같은 뼈대의 부분집합이 되도록 설계했다.

## 디자인 방향

덱 자체가 브랜드의 연장이다: Ink Black `#11100E` 바탕 · Warm Bone `#E9E4DA` 텍스트 ·
Oxidized Bronze `#8A5A35` 강조(권한이 걸린 곳에만) · jade/red는 승인/거부 전용.
헤드라인은 세리프(익스플로러의 display와 같은 목소리), 숫자는 크게(60pt+), 주소·해시는 모노.
**bone 규칙**: 장당 bone 면은 최대 하나 — 서명되는 것, 만들어지는 것에만.
스크린샷은 실제 배포 사이트에서 캡처(목업 금지 — 접속 가능한 실물이 있는데 목업을 쓰면 오히려 의심).

## 본편

### 1. 표지 [갱신]
- **헤드라인**: 마패 MAPAE — 에이전트 결제의 권한 레이어
- **요지**: Split Seal 마크 + "AI에게 지갑을 주지 마세요. 범위를 정한 권한만 주세요."
- **시각**: 마크 단독, 하단에 세 줄 — `mapae.pages.dev` · `npx mapae-mcp` · GIWA Sepolia 91342
- 표지에서 이미 "접속 가능"과 "설치 한 줄"이 사실임을 보여준다.

### 2. 문제 — 선택지는 둘뿐이다 [승계]
- **헤드라인**: AI에게 돈을 맡길 방법이 없다
- **요지**: ①개인키를 통째로 준다(한도·대상·기한 못 걺) ②수탁형에 맡긴다(그 회사를 믿어야 함).
  그래서 아무도 안 준다 — **병목은 수요가 아니라 신뢰다.**
- **시각**: 두 선택지 카드, 둘 다 ✕.

### 3. 더 깊은 문제 — 사고가 나면 누구 책임인가 [승계]
- **헤드라인**: 한도를 걸어도 남는 질문
- **요지**: 다른 체인 `결제 → 0x7a3f… → ?` vs 기와+마패 `결제 → 마패 → 도장 → 실명`.
  책임 주체를 특정 못 하면 보험 인수도 불가능하다.
- ⚠️ [검증 필요] 기존 덱의 "IMF Know-Your-Agent" 인용 — 원문 확인 후 유지/삭제 결정.

### 4. THE GAP — 38 대 0 [승계+재프레임: 비교가 아니라 실측 보고]
- **헤드라인**: 업계에서 가장 감사된 위임 조건 38개를 전수 조사했다
- **요지**: 금액·기간·횟수·대상·시간 — 전부 있다. **신원을 조건으로 거는 것: 0.**
  다른 체인에는 게이트할 신원이 없기 때문이다.
- **관계 뒤집기(하단 두 줄, 필수)**: "그 37개는 감사본 그대로 우리 매니저에서 돈다 — 우리는
  표준을 발명하지 않는다. 이 표준(ERC-7710)은 지갑 중립이다 — **기와 월렛이 채택하는 날,
  같은 조건들이 그 안에서 돈다.**"
- MetaMask는 경쟁사가 아니라 **상속하는 감사 자산의 출처**로만 등장한다(브랜드명은 부제로).
  "기와 월렛을 쓸 건데 왜 남의 지갑 얘기냐"는 질문이 이 두 줄로 소멸한다.
- **시각**: 38과 0, 두 숫자만 거대하게.

### 5. 기와에는 있다 — 그리고 빠진 네 번째 칸 [승계+갱신]
- **요지**: 도장(신원)·UP.ID(이름)·보자기(프라이버시)는 전부 "누구인가"에 답한다.
  "누가 나 대신 움직일 수 있는가"는 비어 있다. 마패 = 네 번째 프리미티브.
- **시각**: 프리미티브 4칸, 마지막 칸이 비어 있다가 채워지는 구성.
- ⚠️ [검증 필요] "신한은행 의사 자격 검증" 문장 — 출처 확인 후 유지/삭제.

### 6. 이름 — 한도가 청동에 새겨져 있었다 [승계+고증 보강] ★사용자 요청 반영
- **헤드라인**: 한도가 청동에 새겨져 있었다
- **부제**: 마패는 비유가 아니라 사양이다 — 이름이 곧 설계도였다
- ("동형"이라는 단어는 쓰지 않는다: 수학 어휘라 아는 사람에게만 멋있다. 매핑 표가 그 말 없이
  같은 일을 한다.)
- **요지(고증)**: 마패는 상서원이 발급한 구리 패. 뒷면에 새겨진 **말의 수가 곧 역참에서 징발할
  수 있는 말의 수** — 품계에 따라 차등 지급됐다(왕 십마패·영의정 칠마패 기록, 현존 유물은
  일마패~오마패). 관원 신분 증명을 겸했고, 암행어사의 상징이 됐다.
- **동형 매핑 표(승계 확장)**:
  | 조선의 마패 | 우리의 마패 |
  |---|---|
  | 신원 검증된 관원에게만 발급 | 도장 보유자의 서명으로만 발급 |
  | 말의 수 = 권한의 크기(품계별 차등) | 서명된 한도 = 권한의 크기(정책별 차등) |
  | 역참이 사용 시점에 패를 확인 | enforcer가 결제 시점에 조건을 확인 |
  | 삼마패로 네 필은 못 끈다 | 캡 초과분은 1원도 못 쓴다 (T2/P4 tx) |
  | 임무·기한이 정해져 있음 | 수취인·만료가 서명에 박혀 있음 |
- **커스텀 조합 연결**: "품계가 말의 수를 정했듯, 오늘의 위임자는 조건의 조합을 정한다" —
  Composer 프리셋/직접 구성 스크린샷 소형 배치. (2마패/3마패의 세부 품계 매핑은 사료가
  구체 표를 주지 않으므로 **구조만 말하고 품계표는 지어내지 않는다.**)
- **마무리 카피(신규)**: "조선의 마패는 위조할 수 있었다 — 청동 조각이었으니까.
  이것은 쓰일 때마다 중심을 다시 얻어야 한다."

### 7. 작동 원리 — 위임 사슬 [승계+갱신]
- **요지**: 실명 이용자(도장) → 마패(범위 서명, **무료·무흔적**) → 에이전트(위임 실행) →
  결제(온체인 정산). 역추적은 결제에서 거꾸로 실명까지. **범위 강제는 프롬프트가 아니라
  컨트랙트가 한다.** ERC-7710/7715 · x402 v2 erc7710.
- **추가(신규)**: 재위임 = 좁히기만 가능, 루트 킬스위치가 사슬 전체 관통 (2홉 라이브 tx 존재).
- **기업 독자용 한 줄(선택)**: "AWS가 클라우드 자원에 IAM을 줬듯, 마패는 에이전트 지출에
  IAM을 준다 — 단 역할표도 관리자도 없이, 서명으로." (RBAC이 아니라 capability+ABAC:
  역할 조회가 아니라 들고 온 서명된 능력을 검증하고, 도장은 결제 순간 읽는 라이브 속성이다.
  이 구분은 덱에서는 한 줄, 기술 상세 자료에서 한 단락.)

### 8. 킬스위치 2×2 [신규 — 데모의 심장]
- **헤드라인**: 두 개의 스위치, 서로 독립, 각각 가역
- **요지**: T5 위임 OFF→거부 / T6 위임 ON→**재개(리셋 아님)** / T7 도장 취소→거부 /
  T8 재발급→재개. 신원 스위치는 **트랜잭션 없이** 모든 마패를 한 번에 멈춘다.
- **시각**: 2×2 매트릭스, 각 칸에 실제 tx 해시 + 익스플로러 추적 링크.

### 9. THE POINT — 모든 조건이 멀쩡한데 실패한다 [승계, 넘버링 T5→**T7** 정정]
- **요지**: ✓서명 유효 ✓한도 남음 ✓기한 유효 ✓수취인 허용 → ✕ `NotDojangVerified`.
  실명 증명이 취소되었다는 이유 하나로. **파는 것은 결제가 되는 것이 아니라, 안 되는 것.**
- **시각**: 체크 4개 + 붉은 거부 1개. 우리 익스플로러의 실제 거부 페이지 스크린샷
  (거부한 조건이 붉게 표시된 그 화면 — 페이지가 이 슬라이드를 그대로 그려준다).

### 10. 제품 — 접속 가능한 웹사이트 [신규] (산출물 ②의 증거)
- **헤드라인**: mapae.pages.dev — 백엔드 0, 모든 값은 방금 체인에서 읽은 것
- **요지**: 3면 — 발급(문장으로 읽고 서명, 가스 0) · 내 권한(지출 미터+킬스위치) ·
  추적(거부한 조건을 체인 안에서 지목). **사람이 MetaMask로 서명한 왕복 4건(P1~P4)** —
  스크립트 자작극이 아니라 제품 경로의 증명.
- **시각**: 스크린샷 3장(한국어 화면). 하단: "발급만 되고 안 쓰인 마패는 체인에 없다 —
  발급은 흔적 없는 무료 서명" (경계를 기능으로 서술).

### 11. 에이전트 통합 — MCP [신규]
- **헤드라인**: MCP를 말하는 모든 에이전트가 이미 마패의 클라이언트다
- **요지**: `npx mapae-mcp` (npm 공개 발행). 도구 6종 표 — 그리고 **issue 도구가 없는 것이
  설계다**: 발급은 사람의 서명, 사용·재위임은 에이전트의 자율. `request_permission` →
  프리필 링크 → 사람은 문장 읽고 서명 → `load_context`로 대화 안에서 인계 완료.
  `pay`는 수취인이 인자가 아니라 **서명된 정책에서 나오므로** 프롬프트 인젝션으로도
  엉뚱한 주소로 못 보낸다.
- **시각**: 실제 PAID / REFUSED JSON 응답(하네스 출력 그대로) + 설치 한 줄.
- **연결**: 이 요청 흐름이 ERC-7715의 실구현 — "기와 월렛이 7715를 켜는 날, 통합이 아니라
  스위치다."

### 12. x402 정산 [신규]
- **헤드라인**: GIWA에서 사실상 유일하게 동작하는 x402 경로
- **요지**: `402 Payment Required` → erc7710 정산 라이브 5단계. **한 서명 payload로 정산 2회**
  (= exact 스킴 3방식 중 유일한 multi-use). facilitator는 조건도 도장도 모르는
  **무지·무권한 정산자** — 정책 엔진 전체가 온체인이라서. GIWA에 EIP-3009 토큰이 없어
  다른 두 방식은 애초에 불가(문서화된 격차).
- **시각**: 5단계 시퀀스 + 2홉 체인 카드 스크린샷.

### 13. SHIPPED, NOT PROMISED — 숫자판 [갱신]
- **숫자(제출 직전 재확인 후 확정)**: 컨트랙트 **8 배포+전수 소스 검증**(+factory가 찍는
  MapaeAccount) · 테스트 **153** · Slither **0/0** · 라이브 tx **25+** · 3언어 바이트 패리티 ·
  npm 패키지 1 · 공개 URL 1 · 백엔드 **0**
- **부제(승계)**: 검증이 실제로 잡은 결함 — ModeLib 시프트 4종(공허 통과 테스트에 가려짐),
  서명 페이로드 사본 드리프트, RPC 경쟁 조건들. "테스트 수가 아니라 테스트가 잡은 것을 센다."
- MetaMask의 감사본 enforcer가 **우리 매니저에서 무수정으로 도는 것**이 호환성 증명.

### 14. 만들지 않은 것 [승계]
- 지갑(기와 월렛을 쓴다) · 스테이블(원화 스테이블을 기다린다 — 자산 불가지론 실증) ·
  번들러/페이마스터(기와 인프라 소비) · 위임 표준(7710/7715 채택) · ERC-8004(빈 배포는
  기여가 아니다) · **자체 백엔드**(권한의 존재는 체인만이 답한다).
- 심사자에게 가장 신뢰를 주는 장 — 그대로 살린다.

### 15. 시장 — 신원은 상대방을 위한 것이다 [신규, 최약점 정면 대응]
- **헤드라인**: 나는 내가 누군지 안다. 모르는 건 내 에이전트의 결제를 받는 쪽이다
- **요지**: ①가맹점 수용성(환불·분쟁의 상대가 될 실명이 사슬 끝에 있어야 에이전트 결제를
  받는다) ②규제 결제(트래블룰·AML — 실명 규제 환경이 도장을 만들었고, 같은 환경이 마패를
  요구한다) ③자격 연동 지출(법인 경비·복지 바우처 — 자격 상실 = revoke 한 번 = 전 지출 정지)
  ④연령·적격 게이트.
- **정직한 현재**: 실사용자 0. 대신 — "심사위원이 오늘 직접 심사할 수 있다: 접속, 발급, 설치."

### 16. 로드맵 + 클로징 [재작성]
- **축을 5개월 → 선발(8/14)~데모데이(10월 KBW) 6~7주로 재설정**:
  W1-2 기와 월렛팀과 7715 스위치 협의 + x402 MCP 통합 / W3-4 Ponder + **도장 조회 API 공개**
  (GIWA 최초) + localhost 콜백 / W5-6 코호트 팀 연동 · 데모데이 리허설.
  이후: EIP-7702 경로(활성 실측 완료) · 가스 대납(번들러 격차 해소 시).
- **구조적 확장성 두 문장**: "지갑이 생기기 전에 지갑의 언어를 구현했다 — 탑재는 통합이 아니라
  스위치다." / "신원 발급자는 배포 상수가 아니라 서명되는 선택이다 — 도장 생태계가 자랄수록
  마패는 코드 변경 없이 넓어진다."
